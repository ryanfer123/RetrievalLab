Before your first run

A few useful details.

Where does my experiment live?

The local app saves experiments in SQLite on your computer. The hosted site sends your dataset to its Python API for computation and keeps your working results temporarily in this browser tab. Export a file or choose Cloud workspaces to sign in and save a private cloud copy. Only an explicit cloud save creates that copy.

What do the metrics mean?+

Precision divides relevant returned hits by the requested cutoff k. Recall measures the share of known relevant documents retrieved. MRR rewards an early first relevant result. Binary nDCG rewards relevant documents near the top of the ranking. The workspace averages these values across labeled queries.

Does this evaluate generated answers?+

No. RetrievalLab evaluates lexical retrieval rankings against relevance judgments. It does not generate answers, validate an answer’s factual correctness, or measure end-to-end RAG performance.

What happens if fewer than k documents match?+

Zero-score documents are omitted. Precision still divides relevant hits by k, so unreturned positions reduce precision. An out-of-vocabulary query can return no matches.

Can I reproduce a run outside the browser?+

Yes. The command-line evaluator accepts the same dataset JSON and cutoff. For the same inputs, configuration, and version, rankings, metrics, and dataset hashes are deterministic. Timestamps, experiment IDs, and latency measurements vary.

Do the sample results show that a method is better?+

No. The included corpus is tiny and hand-authored to demonstrate the workflow. Its scores are not evidence of ranking superiority or performance on an external benchmark. Use judgments and a corpus appropriate to your own evaluation question.
